# 业务流程梳理

本文档描述当前 FoundIt 校园失物招领平台的业务流程。早期设想中的 QQ 机器人、历史数据采集、自动落库匹配等能力仍作为后续方向保留，当前已实现能力以本文为准。

## 1. 角色与权限

| 角色 | 能力 |
| --- | --- |
| 未登录用户 | 浏览物品库、搜索公开物品、发布匿名招领、上传图片并使用图片识别、使用基础智能客服。 |
| 登录用户 | 发布寻物、发布实名招领、填写联系方式、提交认领/联系申请、查看个人发布、申请和通知。 |
| 管理员 | 管理用户角色、管理物品、查看申请、发送系统通知、处理异常数据。 |

隐私原则：

- 公开页面和智能客服默认不直接展示手机号、QQ、邮箱、学号、证件号、二维码内容、条形码内容或完整姓名。
- 需要联系发布者时，应登录后进入详情页，按平台流程提交认领或联系申请。

## 2. 招领发布流程

招领表示用户捡到了物品，希望寻找失主。

```text
进入发布页
  -> 选择“招领”
  -> 可上传图片
  -> 可调用图片识别辅助填写
  -> 填写物品名称、分类、描述、捡到地点、存放处
  -> 未登录用户可匿名发布，但不能填写联系方式
  -> 登录用户可填写联系方式和可见性
  -> 后端保存记录并生成物品向量
```

图片识别当前调用学校 GenAI API 的 `GPT-5.5`，只提取图片中明确可见的物品特征，并输出结构化 JSON 草稿：

```json
{
  "item_name": "",
  "item_type": "",
  "description": "",
  "notes": []
}
```

用户提交前应检查识别结果，不准确或不希望公开的信息需要手动修改。

## 3. 寻物发布流程

寻物表示用户丢失了物品，希望找回。

```text
登录
  -> 进入发布页
  -> 选择“寻物”
  -> 填写物品名称、分类、描述、丢失地点、丢失时间
  -> 可上传图片或使用图片识别辅助填写
  -> 填写联系方式和可见性
  -> 提交
  -> 后端保存记录并生成物品向量
  -> 前端可调用发布前匹配查看疑似相反方向物品
```

当前未登录用户不能发布寻物信息。

## 4. 物品搜索流程

用户在物品库可以：

- 按方向筛选：寻物 `lost` / 招领 `found`。
- 按分类筛选。
- 按状态筛选。
- 输入关键词或自然语言查询。

搜索分为两类：

| 搜索方式 | 接口 | 说明 |
| --- | --- | --- |
| 关键字搜索 | `GET /api/search` | PostgreSQL `ILIKE`，适合精确名称和描述匹配。 |
| 混合语义搜索 | `GET /api/semantic-search` | BM25L + Qwen embedding + pgvector + RRF，适合自然语言和别名。 |

当前搜索只使用物品名称、分类、描述和图片向量，不把地点和时间作为公开搜索主信号。地点只作为展示信息和发布前匹配弱重排信号。

## 5. 发布前匹配流程

发布页可在提交前检查疑似匹配：

```text
用户填写物品信息
  -> POST /api/match-check
  -> 后端只查询相反方向 active 物品
  -> BM25L + 向量召回
  -> RRF 融合
  -> 分类/名称/地点规则重排
  -> 返回候选
```

方向规则：

- 用户发布寻物 `lost` 时，只匹配招领 `found`。
- 用户发布招领 `found` 时，只匹配寻物 `lost`。

这一步返回的是“疑似线索”，不代表系统确认归属。

## 6. 认领与联系申请流程

当用户看到疑似自己的物品或能帮助他人的寻物信息：

```text
登录
  -> 进入物品详情页
  -> 提交认领申请或联系申请
  -> 后端创建 claim_requests
  -> 相关用户收到通知
  -> 管理员或发布者按线下核验结果处理
```

同一用户对同一物品的同类申请会做唯一性约束，避免重复提交。

## 7. 通知流程

通知用于：

- 认领申请提醒。
- 联系申请提醒。
- 管理员系统公告。
- 后续可扩展为自动匹配提醒。

用户登录后可以查看通知列表和未读数，并将通知标记为已读。

## 8. 智能客服流程

客服入口是网站右下角悬浮窗口：

```text
用户发送消息
  -> POST /api/support/chat
  -> CSRF 校验和限流
  -> 判断意图
  -> 检索知识库 RAG
  -> 必要时检索物品库或个人数据
  -> 调用学校 GPT-5.5
  -> 返回回答和 sources
```

意图：

| 意图 | 场景 |
| --- | --- |
| `platform_help` | 平台使用、登录、发布、隐私、流程说明。 |
| `item_search` | 用户询问丢失/捡到/寻找某个物品。 |
| `personal_data` | 登录用户询问自己的发布、申请、通知等。 |

客服物品查询使用和 `/api/semantic-search` 同类的混合检索。若找到候选，回答必须列出相关物品，并说明只是相似线索、不能确认归属。

客服 sources 策略：

- 平台问答不展示知识库来源。
- 个人数据查询不展示个人数据来源。
- 只有物品查询展示脱敏物品来源。

## 9. 客服知识库维护流程

客服知识库来自：

```text
doc/support/*.md
```

维护方式：

1. 修改 `doc/support/` 下的 FAQ、使用指南、搜索指南、隐私说明等 Markdown。
2. `SUPPORT_AUTO_IMPORT=1` 时，执行 `bash dev-local.sh start/restart/db` 会自动同步。
3. 需要立即强制刷新时，执行 `bash dev-local.sh support-import`。

知识库同步是增量的：内容哈希不变且 embedding 不缺失时会跳过。

## 10. 数据与向量流程

物品向量：

```text
物品名称 + 描述 + 图片
  -> Qwen/Qwen3-VL-Embedding-2B
  -> 1536 维向量
  -> lost_items.vector
```

客服知识库向量：

```text
doc/support/*.md
  -> Markdown 切片
  -> Qwen 文本 embedding
  -> support_knowledge_chunks.embedding JSONB
```

如果 embedding 或 pgvector 不可用：

- 物品搜索退回 BM25L/关键词能力。
- 客服知识库检索退回 BM25L。
- 基础功能仍可运行，但自然语言匹配质量会下降。

## 11. QQ 机器人后续扩展

QQ 机器人尚未接入，但后端已经为多渠道预留：

- `/api/support/chat` 支持 `channel=qq`。
- QQ bot 可以调用同一套 RAG 和物品搜索。
- QQ 群里只适合返回脱敏搜索结果和流程说明。
- 涉及个人记录、联系方式、认领处理时，应引导用户回网站登录。

后续需要补充：

- QQ 身份绑定或一次性授权码。
- 群消息限流。
- 群内回复格式。
- 管理员审核和风控策略。

## 12. 通用部署流程

本地推荐流程：

```bash
bash dev-local.sh setup
bash dev-local.sh start
```

局域网入口可由 nginx 提供：

```text
http://your-lan-ip/
http://your-host.example/
```

没有配置 HTTPS 时，访问域名必须显式使用 `http://`。当前服务器的具体入口见 [server-local.md](server-local.md)。
